# Team Memory — 多 agent 共享记忆层

用项目仓库里的两个 Markdown 文件充当所有 agent 的共享记忆：接手时读结论而不是通读代码库，
收工时留下蒸馏过的交接记录而不是过程录像。本 skill 负责搭建和执行协议；让"没加载本 skill 的
agent 也遵守"靠写入项目 AGENTS.md 的协议段落（见初始化）。

## 两个文件，一个分工

- `.memory/STATE.md` — 活文档，当前状态快照。直接改写，永不追加，全文 ≤ 50 行。接手者只读它就能接上。
- `.memory/LOG.md` — 追加式流水账，最新记录在最上面，每条 ≤ 10 行。只在需要历史细节时才读前几条。

写不下的细节一律进 git commit message；记忆文件只存结论和文件清单。

**记忆分层**：STATE.md 是工作记忆（热层，每会话必载的最小上下文），LOG.md 是情景记忆
（冷层，发生过什么，按需检索），AGENTS.md 协议是语义记忆（规则层，不过期）——
分层思想借鉴 MemOS，但用两个 Markdown 文件实现，零基础设施。

## 接手时（新会话开始、接到涉及项目的任务）

1. `.memory/` 不存在 → 走下面的"初始化"。
2. 读 `.memory/STATE.md`（必读）。
3. 仅当任务与历史细节相关时，再读 `.memory/LOG.md` 前 3-5 条和 `git log --oneline -15`。
4. 用一两句话向用户复述"项目当前状态 + 你要做的任务"，确认理解一致后再动手。

## 收工时（完成一个阶段性工作）

1. 改写 `.memory/STATE.md`：完成项移入"近期完成"；"正在做"反映真实进度；"下一步"写清接手者要做的事。
2. 在 `.memory/LOG.md` 顶部追加一条：

   ```
   ## YYYY-MM-DD HH:mm · <agent名或工具名>
   - 做了：<一句话结论>
   - 改动：<文件/目录清单>
   - 遗留：<未完成的事、坑、给下一个 agent 的提醒；没有写"无">
   ```

3. 项目用 git 时把记忆文件一并 commit——它是要随仓库传播的。

## 初始化（项目还没有记忆层时）

1. 创建 `.memory/STATE.md`：

   ```markdown
   # 项目状态（活文档 · 最后更新：YYYY-MM-DD HH:mm by <agent>）

   ## 正在做
   -

   ## 下一步
   -

   ## 近期完成
   -

   ## 坑与约定
   -
   ```

2. 创建 `.memory/LOG.md`：

   ```markdown
   # 操作日志（只追加，最新在上）

   ## YYYY-MM-DD HH:mm · <agent名或工具名>
   - 做了：
   - 改动：
   - 遗留：
   ```

3. 把下面的协议段落追加到项目 `AGENTS.md`（没有则创建；已有"Agent 记忆协议"段落则跳过）：

   ```markdown
   ## Agent 记忆协议（每个会话必做）

   开工前：
   1. 读 .memory/STATE.md（必读，很短）
   2. 仅当任务需要历史细节时，再查 .memory/LOG.md 和 git log --oneline -15

   收工前（阶段性工作结束）：
   1. 更新 .memory/STATE.md：完成项移出"正在做"，更新"下一步"
   2. 在 .memory/LOG.md 顶部追加一条记录（日期/agent 名/结论/改动文件/遗留），≤ 10 行

   纪律：STATE.md 直接改写不追加；LOG.md 只追加；细节写进 commit message；
   「正在做」两周没动就更新或回退；不把密钥、token 等敏感信息写入记忆文件。
   ```

4. 若项目已有 `.memory/` 但 AGENTS.md 缺协议段落，主动补上并告知用户。

## 纪律

- STATE.md 被整体改写是设计意图，不要保留旧全文——历史归 LOG.md 和 git。
- 「正在做」条目超过两周未动：要么更新状态写明停滞原因，要么移回「下一步」——过期条目让 STATE 的可信度腐烂。
- LOG.md 只追加不改写；发现旧记录有误时追加一条更正，不动原文。
- 每条 LOG ≤ 10 行；超过的细节进 commit message。
- 不把密钥、token、内网地址写入记忆文件——它们会进 git 历史。
- 记忆文件必须入库：`.gitignore` 不要排除 `.memory/`。
- 多个 agent 并发收工产生 git 冲突时，两条日志都保留，交给下一个 agent 合并。
