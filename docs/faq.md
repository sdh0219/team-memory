# 常见问题

**Q1：记忆文件会不会污染仓库历史？**
会进历史，但这正是设计意图——它就是项目的操作账本，和代码一起版本化。嫌多的话
`.memory/LOG.md` 超过 100 条时可以整卷归档成 `LOG-archive.md`，主文件只留最近的。

**Q2：多个 agent 同时收工，都改 STATE.md 怎么办？**
真正的并发写很少见（多数场景是接力）。真撞了就 git 冲突解决：两条 LOG 都保留，
STATE 手工合并——它的四节结构让手工合并非常快。

**Q3：和我已经在用的 Claude Code / ZCode 自带记忆有什么区别？**
自带的用户记忆是"每个工具一份、跟随用户"，管的是你的偏好；team-memory 是"项目一份、
跟随仓库"，管的是项目进度和交接。前者回答"这个人喜欢什么"，后者回答"这个项目到哪了"。
两者互补，不冲突。

**Q4：为什么不用向量库 / 记忆服务（MemOS、mem0）？**
光谱另一端的重方案，解决海量记忆的存储调度。而"下一个 agent 花最少 token 接上进度"
这件事，一个 50 行的活文档比任何检索系统都准、都便宜。等你的记忆规模真需要检索了，
再上重方案不迟——这两个 Markdown 文件就是那时的种子数据。

**Q5：STATE.md 和 git log 不是重复吗？**
git log 记录"改了什么文件"，STATE 记录"项目现在什么状态、下一步干什么"。
后者需要跨 commit 归纳，恰恰是 agent 每次重读全部历史才能得到、最该被缓存的结论。

**Q6：多久清理一次 LOG？**
不用清理。它是追加式账本，只在需要溯源时被读前几条。强迫症发作时按 Q1 归档即可。

**Q7：私有仓库/公司项目能用吗？**
协议本身就是几个文件加一段文字，任何 git 环境、任何 agent 都适用。注意 Q：敏感项目
确保 `.memory/` 不进公开镜像即可。

**Q8：agent 不听话，不写记忆怎么办？**
三道保险：装 skill（主动触发）→ AGENTS.md 协议段（被动约束）→ 你在对话里说一句
"更新一下项目记忆"（人工兜底）。第三道永远有效。
