# team-memory 协议规范

本文是协议的完整定义。装了 skill 的 agent 由 skill 驱动执行；没装 skill 的 agent 靠项目
`AGENTS.md` 里的协议段落执行——两者内容一致。

## 1. 总览

三件套：

| 组件 | 位置 | 作用 |
|---|---|---|
| 状态快照 | `.memory/STATE.md` | 当前项目状态，接手者的唯一必读物 |
| 交接日志 | `.memory/LOG.md` | 追加式流水账，按需翻阅的历史细节 |
| 协议段落 | `AGENTS.md` | 告诉每个 agent 何时读、何时写、怎么写 |

## 2. STATE.md 规范

固定四个小节，一节都不能空着长期放着：

| 小节 | 内容 |
|---|---|
| `## 正在做` | 当前进行中的事，每项一行，写明卡在哪 |
| `## 下一步` | 接手者应该做的事，按优先级排列，写清入口（文件/文档） |
| `## 近期完成` | 最近 3-5 条，一行一条：日期 + 一句话结论 + 谁 |
| `## 坑与约定` | 踩过的坑、必须遵守的项目约定，这是全文件最值钱的一节 |

- 全文 **≤ 50 行**；写不下说明在记过程而不是结论
- **直接改写，永不追加**：旧内容被新状态替换是设计意图，历史归 LOG.md 和 git
- 文件头标注最后更新时间与执行者，方便判断新鲜度

## 3. LOG.md 规范

条目固定三字段，最新条目置于文件顶部：

```
## YYYY-MM-DD HH:mm · <agent名或工具名>
- 做了：<一句话结论>
- 改动：<文件/目录清单>
- 遗留：<未完成的事、坑、给下一个 agent 的提醒；没有写"无">
```

- 每条 **≤ 10 行**；细节写进 commit message，条目里只写结论和文件清单
- **只追加，不改写**：发现旧条目有误，追加一条更正，不动原文
- 接手时默认只读前 3-5 条；需要更早的历史再往下翻

## 4. AGENTS.md 协议段

初始化时写入项目 `AGENTS.md`（没有则创建）：

```markdown
## Agent 记忆协议（每个会话必做）

开工前：
1. 读 .memory/STATE.md（必读，很短）
2. 仅当任务需要历史细节时，再查 .memory/LOG.md 和 git log --oneline -15

收工前（阶段性工作结束）：
1. 更新 .memory/STATE.md：完成项移出"正在做"，更新"下一步"
2. 在 .memory/LOG.md 顶部追加一条记录（日期/agent 名/结论/改动文件/遗留），≤ 10 行

纪律：STATE.md 直接改写不追加；LOG.md 只追加；细节写进 commit message；
不把密钥、token 等敏感信息写入记忆文件。
```

## 5. 与 git 的分工

- 细节的最终归宿是 **commit message**：LOG 条目只留结论，写不下就引 commit
- 记忆文件**必须入库**：`.gitignore` 不要排除 `.memory/`，clone 即带走
- 并发收工产生 git 冲突时，两条日志都保留，交给下一个 agent 合并
- 单独长期分支上的实验可以暂不记，合并回主线时补一条总账即可

## 6. 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 把 STATE.md 当日志往上追加 | 几百行，没人读完 | 直接改写，≤ 50 行 |
| LOG 条目记过程流水账 | 每条几十行， token 白烧 | 只写结论，细节进 commit |
| 收工不更新记忆 | 下一个 agent 盲人开局 | 收工写记忆和写代码同等重要 |
| 密钥/token 写进记忆文件 | 进 git 历史，删不掉 | 敏感信息只走环境变量 |
| 只装 skill 不写 AGENTS.md | 没装 skill 的 agent 不遵守 | 协议段落进 AGENTS.md，双保险 |
